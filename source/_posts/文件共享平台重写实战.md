> **项目背景**：公司内部文件共享管理平台（FileSharedPlatform）重写项目。
> **核心目标**：将"创建共享后还需人工到文件服务器运行脚本"的旧系统，重写为"点击即共享"的新系统。
> **技术栈**：.NET Core 8 + Vue 3 + SQL Server + SSH.NET。

---

## 一、为什么要重写：旧系统的核心缺陷

旧系统是一个基于 **ASP.NET Web Forms (.NET Framework 4.5)** 的文件共享平台，核心逻辑全部在编译好的 DLL 中，**没有源码**。

它存在一个致命缺陷：

> **创建文件共享后，还需要人工到文件服务器上运行脚本才能真正共享。**

具体表现为：
- 管理员在 Web 界面点击"创建共享"，系统**只把共享信息写入数据库**，**没有真正在文件服务器上创建共享文件夹**
- 文件服务器上的共享目录需要人工通过 `net share` 命令创建
- 权限设置需要人工通过 `icacls` 命令配置

也就是说，旧系统**只管理数据库记录，没有与文件服务器联动**。每次创建共享，管理员都要跑到文件服务器上敲命令，效率极低且容易出错。

---

## 二、重写目标：实现"点击即共享"

新系统的核心目标是：**用户在 Web 界面点击"创建共享"后，系统自动在文件服务器上创建共享文件夹、设置权限、更新数据库，无需人工到文件服务器上执行任何脚本。**

同时要满足：
- 支持共享文件夹的**增、删、改、查、续期**完整生命周期管理
- **既能管理新创建的共享，也能修改旧的共享**
- **不影响现有共享目录**（数据是 TB 量级，不能重新复制）

---

## 三、技术选型

| 层 | 旧系统 | 新系统 |
|----|--------|--------|
| **前端** | HTML + jQuery | Vue 3 + Element Plus + Vite |
| **后端** | ASP.NET Web Forms (.NET 4.5) | .NET Core 8 + ASP.NET Core Web API + Dapper |
| **数据库** | SQL Server（存储过程） | SQL Server（复用现有存储过程） |
| **远程执行** | 无（人工操作） | SSH.NET 远程执行共享命令 |
| **认证** | AD 域认证 + Token | JWT |
| **日志** | 无 | Serilog |

**关键决策**：
- **复用现有数据库**（HIKVISIONFileShare_DB），保留现有表结构和存储过程，降低迁移风险
- **通过 SSH.NET 远程执行**共享命令，实现"点击即共享"
- **完全独立部署**，与旧系统并行运行，逐步迁移用户

---

## 四、服务器架构

| 服务器 | 角色 | 说明 |
|--------|------|------|
| **FSS1** | 文件服务器 1 | 共享根目录为 **E 盘**，已有 TB 量级共享目录 |
| **FSS2** | 文件服务器 2 | 有 **D 盘**和 **F 盘**，已有 TB 量级共享目录 |
| **FSDB** | 数据库服务器 | 运行 SQL Server（HIKVISIONFileShare_DB） |
| **FSPLF1/FSPLF2** | 前端服务器 | 部署 Vue 前端（Nginx 托管） |

**关键约束**：
1. FSS1 和 FSS2 的共享根目录路径不同，需分别配置
2. 数据是 TB 量级，不能重新复制，必须复用现有共享目录
3. 现有共享目录必须保持不变，不能影响现有业务
4. 新系统创建共享时，在各自的共享根目录下新建子文件夹

## 五、核心实现：点击即共享

### 5.1 创建共享流程

```
用户点击"创建共享"
    ↓
Vue 前端 → POST /api/folder
    ↓
Web API → FolderService.CreateFolder()
    ↓
① 验证 Token
② 检查参数（文件夹名、授权码、权限列表）
③ 获取文件服务器（spAFSFS_GetFileServerForAccreditID）
④ SSH 连接文件服务器，执行共享命令
⑤ 插入文件夹记录（spSFFS_Insert）
⑥ 插入权限记录（spFPFS_Insert）
    ↓
返回共享成功
```

### 5.2 文件服务器共享命令

**创建共享（在共享根目录下新建子文件夹）：**
```powershell
# 1. 创建本地目录
mkdir "E:\共享文件夹名"

# 2. 创建共享（共享名 = 文件夹名）
net share "共享文件夹名"=E:\共享文件夹名 /grant:everyone,READ

# 3. 设置 NTFS 权限（编辑者：修改；只读者：读取）
icacls "E:\共享文件夹名" /grant "DOMAIN\编辑者账号:(OI)(CI)M"
icacls "E:\共享文件夹名" /grant "DOMAIN\只读者账号:(OI)(CI)R"
```

**删除共享：**
```powershell
net share "共享文件夹名" /delete
rmdir /s /q "E:\共享文件夹名"
```

**修改权限（支持修改旧共享）：**
```powershell
icacls "E:\共享文件夹名" /reset
icacls "E:\共享文件夹名" /grant "DOMAIN\编辑者账号:(OI)(CI)M"
icacls "E:\共享文件夹名" /grant "DOMAIN\只读者账号:(OI)(CI)R"
```

## 六、安全设计

### 6.1 SSH 安全
1. **密钥认证**：禁用密码登录，只允许密钥认证
2. **专用账号**：创建专用账号（如 `shareadmin`），加入本地管理员组（因为 `net share`、`icacls` 需要管理员权限）
3. **防火墙限制**：只允许后端服务器 IP 访问 22 端口
4. **命令白名单**：后端只执行预定义的共享命令，不执行任意命令

### 6.2 API 安全
1. **JWT 认证**：所有 API 需要 JWT 令牌
2. **参数校验**：文件夹名只允许中文/字母/数字/下划线/短横线，防止命令注入
3. **SQL 注入防护**：使用 Dapper 参数化查询

## 七、部署要点

### 7.1 文件服务器准备
```powershell
# 安装 OpenSSH Server
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType 'Automatic'

# 创建专用账号并加入管理员组
net user shareadmin "强密码" /add
net localgroup Administrators shareadmin /add

# 配置密钥认证（将公钥添加到 administrators_authorized_keys）
# 配置防火墙（只允许后端服务器 IP 访问 22 端口）
```

### 7.2 后端部署
- 发布 .NET Core Web API，配置 `appsettings.json`（数据库连接、SSH 密钥、文件服务器信息）
- 使用 Kestrel + Nginx 反向代理 或 IIS 托管

### 7.3 前端部署
- 构建 Vue 3 前端，部署到 FSPLF1、FSPLF2（Nginx 托管）
- 配置 Nginx 反向代理 `/api/` 到后端 API

## 九、经验总结与踩坑点

### 9.1 关键经验
1. **复用现有存储过程**是降低迁移风险的关键，新系统只需保证参数一致
2. **SSH 账号必须是管理员**：`net share`、`icacls`、`rmdir /s` 都需要管理员权限，安全靠"专用账号 + 密钥认证 + 防火墙限源 IP"保障，而非降低权限等级
3. **完全独立部署**，与旧系统并行运行，可逐步迁移用户，风险可控

### 9.2 需要注意的坑
1. **存储过程兼容性**：新系统调用现有存储过程，需确保参数完全一致
2. **共享名冲突**：创建共享前需检查共享名是否已存在
3. **权限继承**：`icacls` 设置权限时需注意权限继承关系
4. **回滚机制**：如果数据库操作失败，需要回滚文件服务器上的共享操作
5. **并发控制**：多个用户同时创建共享时，需防止共享名冲突
6. **FSS1/FSS2 差异**：两台文件服务器的共享根目录路径不同，需分别配置
7. **命令注入防护**：文件夹名必须白名单校验，防止恶意命令注入

---

## 十、总结

这个项目最大的价值在于：**把原本需要人工到服务器上敲命令的运维工作，通过 SSH 自动化集成到了 Web 界面中**，实现了真正的"点击即共享"。

对于运维工程师来说，这是一个典型的"**运维开发（DevOps）**"实践——用代码解决重复性人工操作，提升效率、降低出错率。同时，通过**复用现有数据库和存储过程**、**完全独立部署**、**逐步迁移**的策略，将重写风险降到了最低。

如果你也面临类似"旧系统逻辑封闭、无法扩展"的困境，希望这个项目的思路能给你一些启发。
