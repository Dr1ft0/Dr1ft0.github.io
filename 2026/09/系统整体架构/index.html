文件共享平台 · 系统整体架构

本文档描述新系统（.NET 8 Web API + Vue 3 SPA）的整体架构、分层职责、核心链路与各框架的可视化关系。

〇、脱敏声明

本文档不包含任何真实的生产敏感信息。以下内容一律使用占位符表示：

占位符 含义
<DB_HOST> 数据库服务器地址
<DB_NAME> 数据库实例名
<DB_USER> / <DB_PASSWORD> 数据库账号 / 口令
<FSS_IP> 文件服务器地址
<SSH_USER> SSH 专用账号
<KEY_PATH> SSH 私钥文件路径
<JWT_SECRET> JWT 签名密钥
<LEGACY_DES_KEY> 旧系统 DES 密钥

真实值请通过安全配置管理（密钥保管、环境变量、受控配置文件）维护，不要写入任何纳入版本管理的文档。

一、系统定位

企业内部的文件共享管理平台：管理员通过 Web 界面登记、授权、管理文件服务器上的共享文件夹（增删改查 + 续期 + 日志）。

新旧系统核心差异

维度 旧系统 新系统
技术栈 ASP.NET Web Forms (.NET Framework 4.5) .NET 8 Web API + Vue 3 SPA
核心逻辑 全部编译在 DLL 中，无源码 完全开源、分层清晰
与文件服务器联动 无，只写数据库 有，SSH 远程执行共享命令
共享生效方式 人工上文件服务器跑脚本 点击即共享，全自动
前端交互 HTML + jQuery + AJAX（整页/半页刷新） SPA 单页应用、组件化

要点

  • 后端只监听回环地址，由 Nginx 对外，避免 API 直接暴露。
  • 文件服务器 22 端口仅放行后端服务器来源 IP。
  • 共享根目录按文件服务器分别配置（文件服务器 A 与 B 不同）。

6.2 状态机与补偿

stateDiagram-v2
    [*] --> Validate
    Validate --> CreateOnServer : 参数合法
    Validate --> [*] : 抛 BusinessException
    CreateOnServer --> WriteDb : SSH 执行成功
    CreateOnServer --> [*] : SSH 失败 / 目录已存在
    WriteDb --> Success : 写库成功
    WriteDb --> Compensate : 写库失败
    Compensate --> [*] : 补偿删除已建共享与目录
    Success --> [*]

事务顺序（已确认的设计）：先 SSH 建共享 → 再写数据库 → 写库失败则补偿删除。

# 位置 问题 影响
1 ShareService SSH 连接信息未从配置注入模型 核心链路不可用
2 ShareService 目录存在性判断 Contains("EXISTS") 会匹配 NOT_EXISTS 创建必然失败
3 Program.cs 未配置 JSON camelCase 命名策略 前端读取字段全部 undefined
4 ShareCommandBuilder 共享级权限 everyone,READ 会封顶 NTFS 的 M 权限 编辑者实际无法写入
5 FolderService 修改共享未同步数据库权限表 权限记录与真实权限不一致
6 FolderService ShareStatus 状态跟踪未落库 补偿失败后无法追踪
7 FolderService 未使用 AccreditID 解析文件服务器 授权关系未校验
8 Program.cs UseExceptionHandler 注册在 MapControllers 之后 无法捕获控制器异常
9 SpaceService 已用/剩余/使用率硬编码为 0 空间管理未真正实现
10 仓库根目录 文档与配置含明文生产凭据 严重安全风险
11 package.json 未声明 @element-plus/icons-vue 依赖 构建依赖隐式提升

本文档基于当前代码与配套设计文档整理；涉及存储过程真实签名、SSH 配置归属、登录口令加密方式等仍待确认的事项，以最终确认结论为准。
